## Governing Rules

1. Protect the current implementation before broad research changes.
2. Treat Crypto Wizards as discovery and diagnosis until exact mode parity is
   proven.
3. Require local point-in-time, after-cost Hyperliquid evidence for acceptance.
4. Count independent economic exposures rather than differently named rows.
5. Register every hypothesis before testing and preserve a locked holdout.
6. Treat zero survivors as a valid research outcome.
7. Keep every agent proposal-only until eligible evidence proves otherwise.
8. Require a final 1x survivor and one-run approval before Testnet submission.
9. Require realized Testnet evidence, a fresh Supreme Team review, and explicit
   user authorization before any live canary.
10. Never resolve a blocker by weakening the gate that discovered it.

## Phase 0: Protect And Recover

- Build a hashed baseline and path-by-path commit manifest.
- Exclude credentials, private keys, environments, raw data, and generated
  snapshots from Git.
- Commit and push the reviewed source, configuration, tests, and documentation.
- Create an encrypted backup on a different failure domain.
- Restore into a different location and rerun verification.

Exit: remote source and an independent backup both reproduce the platform.

## Phase 1: Freeze Governance

- Force threshold changes to create a new policy identity.
- Create a semantic cross-run hypothesis ledger.
- Define development, validation, and locked-holdout periods prospectively.
- Attack gate identities and renamed duplicate hypotheses.

Exit: changed policies and renamed hypotheses cannot erase prior evidence or
inherit prior authority.

## Phase 2: Venue, Data, And Costs

  missing pagination.

- Build pair-specific observed-cost models and attack them with stale, sparse,
  cherry-picked, unit-flipped, and sign-flipped evidence.

Exit: candidate data and cost models are current, complete, causal, observed,
and stress-tested.

## Phase 6: Agent And Learning Governance

authority.

## Phase 7: Conditional Testnet

Testnet remains blocked until there is a valid final 1x survivor receipt.

Then:

- verify market, wallet, agent, margin, funding, sizing, and paired recovery;
- submit one bounded 1x paired lifecycle;
- cancel and flatten on mismatch, timeout, unknown response, or reconciliation
  error;
- accumulate outcomes under a policy written before observing them;
- run a new Supreme Team review.

Exit: realized Testnet evidence passes statistical, cost, regime, drawdown, and
operational reliability requirements.

## Phase 8: Live Readiness

Live progression is never automatic.

- Define canary risk limits before live outcomes exist.
- Reconcile shadow, Testnet, and live-market inputs without orders.
- Require explicit authorization bound to one candidate, account, policy, size,
  and time window.
- Use the smallest venue-valid notional.
- Run a post-canary review before any repetition, scaling, or leverage change.

Exit: realized evidence and a fresh Supreme Team review approve the next bounded
step with no unresolved critical blocker.
